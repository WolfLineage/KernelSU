# syscall 时序实测方法（MT 管理器终端）

## 为什么 shell 命令不行

`stat`、`ls` 每次要启动新进程，开销毫秒级；syscall 本身是纳秒级，信号被完全淹没。
必须用原生程序在进程内连续调用 syscall 计时。

## 为什么之前"必须 root"

Android 禁止普通 app 执行 `/data/local/tmp` 下的二进制（SELinux 限制），所以把探针放那里
chmod 777 也跑不起来，只有 root/shell 能执行。但 root 测量的时序不代表普通 app——
KSU 的 allowlist 检查在 root 和 app 下走不同分支，结果会失真。

**本版已解决**：`run.sh` 会把二进制复制到当前 app 的私有 files 目录再执行，
app 可以执行自己私有目录里的二进制，因此**不需要 root**，且测量发生在真实 app uid。

## 操作步骤（推荐：非 root 模式）

1. 把这三个文件放进手机同一目录：`timing-probe-arm64`（或 arm32）、`run.sh`
2. 在 MT 管理器终端（**非 root 模式**）执行：

   ```
   cd <你放的目录>
   sh run.sh arm64
   ```

3. 程序会打印 `[start] uid=... selinux=...`，确认 uid ≥ 10000、selinux 是 app 域。
4. 输出 `newfstatat / statx` 比值及判定。

## 手动执行（若 run.sh 不奏效）

在 MT 终端把二进制复制到 app 私有目录：

```
cp timing-probe-arm64 /data/user/0/bin.mt.plus/files/tp
chmod 700 /data/user/0/bin.mt.plus/files/tp
/data/user/0/bin.mt.plus/files/tp
```

（`bin.mt.plus` 是 MT 标准版包名；订阅版为 `bin.mt.plus.canary`，
先在终端 `cd /data/user/0/` 用 `ls` 确认实际目录名。）

## 参数

```
tp [-r] [-u UID] [路径]
  -r       保持 root（不降权，仅调试用，结果不代表 app）
  -u UID   以 root 运行时降到的 uid（默认 10123）
  路径     被测文件（默认 /system/bin/ls）
```

程序会打印 `selinux=` 上下文和 `uid`。若看到 `WARNING: measuring as uid=0`，
说明这次是 root 测量，不代表 app，请改用非 root 模式重跑。

## 结果判读

核心看这一行：

```
newfstatat / statx = X.XXX  -> NORMAL 或 KSU-LIKE
```

- **< 1.2 / NORMAL**：statx 对齐生效，该时序判据已消除。
- **> 1.2 / KSU-LIKE**：时序信号仍在，确认设备是否刷入了 v3.3.3（32758）对应的内核 LKM。
  APK 更新不会替换内核模块，这一步最容易被忽略。

辅助行：
- `faccessat / statx`：同样 >1.2 判有信号。
- `newfstatat / getpid`：getpid 从不被 hook，作噪声参考。若所有比值都接近 1，说明环境噪声过大。
- `last rc`：若 newfstatat/statx 的 rc 为负，说明该路径此 uid 不可读，换 `/system/bin/ls`。

## 完整性检查

若输出里出现三行 `uid=`/`selinux=` 且 uid ≥ 10000，说明测量身份正确；
若只有一行且带 WARNING，说明在 root 下测的，结果仅供参考。

## 注意事项

- 测量时关闭后台应用，减少调度噪声。
- 结果取 15 轮中位数，已过滤大部分抖动；若反复跑差异很大，说明环境噪声过高。
- 两个二进制均为 NDK 静态链接。现代设备用 arm64，老设备用 arm32。
